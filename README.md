homework1 - Калькуляторы
В этой папке представлена одна и та же задача - создание калькулятора - но реализованная четырьмя разными способами.

1. Базовый (Последовательный): Простой скрипт-калькулятор, который запрашивает у пользователя два числа и математический знак.
- Запрос первого и второго числа с приведением к типу int.
- Запрос математической операции (+, -, *, /, %).
- Ветвление с помощью if/elif для выполнения нужного действия.
- В блоке else по умолчанию реализовано целочисленное деление (//), если введен другой знак.
- Вывод результата в консоль.

2. Функциональный: В этом файле логика математических операций вынесена в отдельные функции для лучшей структуры кода.
- Созданы функции для базовых операций:
ad(a, b) — сложение, sb(a, b) — вычитание, ml(a, b) — умножение, dv(a, b) — деление, int_dv(a, b) — целочисленное деление, fl_dv(a, b) — остаток от деления (в коде обозначена как %)
- В конце файла приведен тестовый вызов функции умножения ml(40, 70) и вывод результата.

3. Универсальный с циклом: Усовершенствованная версия калькулятора, где основная логика выбора операции инкапсулирована в одну функцию.
- Функция f(a, b, c), которая принимает два числа и знак операции, а затем возвращает результат с помощью if/elif.
- Использование цикла while True: для создания интерактивного интерфейса.
- Внутри цикла используются input() для получения данных от пользователя.
- Вызов функции f(a, b, c) и печать результата.
- Команда break для корректного завершения работы программы.

4. Калькулятор метаболизма  (ООП): Программа для расчета базового метаболизма (BMR) и суточного расхода энергии (TDEE). Реализована с применением классов.
- Создан класс daily_energy.
- Конструктор __init__ принимает параметры: вес (weight), рост (height), возраст (age), пол (gender) и уровень активности (activity).
- Метод BMR(self) вычисляет базовый метаболизм по формуле Миффлина-Сан Жеора (с учетом пола).
- Метод TDEE(self) вычисляет суточную норму калорий, умножая BMR на коэффициент активности (zero, light, medium, high).
- Создан объект me с конкретными параметрами и выведены результаты расчетов BMR и TDEE.

homework3 - Лабиринт 
Это процедурно генерируемая текстовая игра-лабиринт на Python. Игрок перемещается по сетке 5x5, исследует комнаты, сражается с монстрами и ищет ключ от выхода.

Ключевые механики и особенности реализации:

Генерация карты: Лабиринт размером 5x5 создается случайным образом. Гарантированно размещаются старт (в левом верхнем углу), выход (в правом нижнем) и ключ (в случайной комнате). Остальные комнаты заполняются случайными событиями: пусто, сундук, монстр, ловушка или портал.
Эмодзи-графика и «Туман войны»: Карта отрисовывается в консоли с помощью эмодзи (⬜️, 🎁, ☠️, ⚠️, 🌀). Игрок видит только те комнаты, в которых уже побывал (неизведанные скрыты под ❓). Текущая позиция игрока отмечается символом 🧍.
Пошаговый бой (fight): При встрече с монстром начинается бой. Игрок может атаковать (урон зависит от наличия меча в инвентаре), выпить зелье для восстановления здоровья или попытаться сбежать (шанс 50%). Монстр наносит ответный удар.
Инвентарь и лут: Сундуки выдают случайный лут (золото, зелья, меч, щит, карта). В инвентаре можно сортировать предметы, выбрасывать их или использовать зелья для лечения (максимальное HP — 100). Щит снижает урон от ловушек.
Телепортация и победа: Портал случайным образом перемещает игрока в другую точку карты. Для победы нужно найти ключ и добраться до выхода.
Управление: Передвижение реализовано через клавиши w/a/s/d. Вызов инвентаря — i, выход из игры — q.

homework5 - Банковский терминал "Pinky Bank" (PyQt6)
Практическая работа по созданию графического интерфейса пользователя (GUI) на языке Python с использованием фреймворка PyQt6. Приложение эмитирует простой банковский терминал для пополнения и снятия средств.

1. Создание графического интерфейса
- Создано главное окно приложения на базе класса QMainWindow с фиксированным размером.
- Реализованы основные UI-элементы:
Заголовки (QLabel) с названием банка и подсказкой.
Информационное табло текущего баланса.
Выпадающий список (QComboBox) для выбора операции («Пополнить» или «Снять»).
Текстовое поле (QLineEdit) для ввода суммы.
Кнопка (QPushButton) для выполнения действия.
Для компоновки элементов использованы вертикальный (QVBoxLayout) и горизонтальный (QHBoxLayout) менеджеры компоновки.

2. Стилизация интерфейса
- Внешний вид приложения вынесен в отдельный файл style.qss.
- Настроена цветовая палитра (розовые и пурпурные оттенки), шрифты и отступы.
- Для кнопок и полей ввода настроены состояния :hover (при наведении) и :focus (при фокусе), а также скругления углов (border-radius).
- Применен стиль Fusion для базовых элементов ОС, чтобы кастомные стили отображались корректно.

3. Реализация бизнес-логики и валидации
- Валидация ввода: Реализована проверка введенной суммы. Обрабатываются следующие случаи:
Пустая строка.
Наличие отрицательного числа.
Ввод нечисловых символов (букв, спецзнаков).
Ввод нулевой суммы.
- Логика операций:
При пополнении введенная сумма прибавляется к текущему балансу.
При снятии проверяется достаточность средств (защита от ухода в минус). Если средств достаточно — сумма вычитается.
- Обратная связь:
При успешном выполнении операции выводится всплывающее окно (QMessageBox.information) с подтверждением.
При ошибках валидации или нехватке средств выводится предупреждение (QMessageBox.warning).
После успешной операции интерфейс обновляется: баланс на экране меняется, а поле ввода суммы очищается.
